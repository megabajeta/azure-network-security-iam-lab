# Azure Network Security and IAM Lab Configured an Azure virtual network, subnet security rules, managed identity access, and administrative change auditing. ## Resources | Resource | Configuration | |---|---| | Resource group | rg-cloud-security-lab | | Virtual network | vnet-security-lab — 10.0.0.0/16 | | Subnet | default — 10.0.0.0/24 | | Network security group | nsg-security-lab — attached to the default subnet | | Managed identity | mi-lab-reader — Reader role at resource-group scope | The VNet and NSG are in East US 2. The managed identity is in East US. ## Network Security Configured two inbound rules: | Priority | Rule | Source | Protocol / Port | Action | |---|---|---|---|---| | 100 | Allow-SSH-MyIP | My public IP, redacted | TCP / 22 | Allow | | 110 | Deny-SSH-others | Any | TCP / 22 | Deny | The intended policy allows SSH from the specified IP and denies other SSH sources. Default NSG rules remain in place. ## Identity and Access Management - Created a user-assigned managed identity without creating a new directory user. - Assigned the Reader role to mi-lab-reader at rg-cloud-security-lab scope. - Verified the assignment appeared as active in Access control (IAM). ## Auditing Reviewed the Azure Activity log and located a successful Create role assignment event. Inspected its initiator, timestamp, and resource path. ## Validation and Limitations Verified the configuration through Azure portal screenshots. No VM was deployed, so live SSH connectivity was not tested. The managed identity was not attached to a workload, so runtime permission tests were not performed. ## Report and Screenshots [Download the lab report](./Azure_Security_IAM_Lab_Report_Public.html), then open it in a browser to view the embedded screenshots. Public screenshots have sensitive identifiers covered using AI-assisted redaction. Original captures are retained separately. ## Skills Demonstrated Azure virtual networking, NSG configuration, managed identities, resource-group RBAC scoping, and activity-log auditing.
